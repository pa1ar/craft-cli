# Jev as a Craft read advisor — live experiments, 2026-09-27

The useful unit is a retrieval decision: given the user question, a short explicit retrieval intent, and a shallow page with previews, select the next useful read or return compact source evidence. This can replace some expensive-agent navigation turns. It is distinct from a general search engine or a second answer-writing agent.

Recommendation after these experiments: continue with explicit advisory calls and bounded branch expansion. Do not install a transparent interception hook or treat a single probability as an authoritative “enough information” gate yet. The experiment scripts are available under [experiments/jev-retrieval](../experiments/jev-retrieval/README.md); production craft-cli is unchanged.

## Real project and protocol

Used Sumr OP, its 21 immediate page children (plus an expandable collection), outgoing links, and matching incoming links. The linked Sumr Trace API project contains two architecture subpages. Craft's shallow JSON includes `contentPreviewMd`, making preview-aware selection possible before fetching descendants. The initial expanded candidate set contained 68 unique targets, 44 with incoming-link evidence; some targets had multiple relation types. Backlink discovery used text search plus exact `block://` matching, not a complete graph scan.

All note access was read-only through the existing Craft 0.8.0 installation on mcFrakir over Tailscale SSH. Jev ran through TypeSafe `jev-1.13.0` from the local Mac. Selected project evidence and snippets were sent to TypeSafe for the user-requested experiments. Raw note text and request traces are retained only under the owner-restricted `~/dev/play/craft-jev/.private/`; Git artifacts contain code and aggregate metrics, not private note snapshots.

The main agent did not intervene inside a router run. Each router invocation performed a bounded internal loop: shallow read → classify current evidence and candidate usefulness → read one selected branch → reassess → select exact excerpts → check the selected evidence. A separate advisory experiment scored valid commands as likely useful versus excessive. Commands were constructed by Python from fetched IDs, never generated by Jev.

These are exploratory, hand-selected, in-sample questions. They are not a randomized full-agent A/B, a blind retrieval benchmark, or a measurement of main-model dollars saved. Timings are single observations, include SSH/CLI overhead, and are sensitive to network variation. Later variants are preserved separately, not pooled into best-of results.

## Observed behavior

| Task | What the experiment did | Assessment |
| --- | --- | --- |
| Current input/provider capabilities and entitlement distinctions | Chose Map Features, returning 11 exact source rows | Correct destination and useful partial evidence. The notes do not certify current App Store entitlements; returning uncertainty is appropriate. |
| Video-source routing and visual analysis, with release caveat | Read hub shallowly, then Map Features; first selector retained two relevant rows | Both requested facts and the implementation-vs-release caveat were present. Final context-preserving variant retained five rows. |
| Find relevant linked material for caching and telemetry infrastructure | Ranked Sumr Trace API OP first among the mixed link/subpage candidates and read it | Useful lead, but no complete mobile-app caching design was found. It did not pretend another related project's infrastructure was the missing answer. |
| Choose between old and updated infrastructure plans inside the linked project | Read Trace shallowly, then selected the updated Notion-prototype subpage | Correct branch. Initial excerpt selection lost “Status: Scoping”; deterministic context retention restored it without an API read. |
| Identify the linked project already named in a task | One shallow read; no expansion; one exact answer row | No additional read was necessary. The conservative completion gate still hesitated, exposing a false-negative gating problem. |
| Locate a signed enterprise 99.99% uptime agreement | No branch exceeded the read threshold; selected no evidence | Appropriate abstention in the retrieved scope. Does not prove no agreement exists anywhere in Craft. |

Manual evidence check: returned source text matched the fetched block text exactly across all inspected packets. For the video question, the selected feature-map paragraph explicitly contained the requested video list and visual-analysis feature; a separate paragraph qualified the inventory as implementation code. For the infrastructure question, the selected architecture paragraph explicitly named the new components and exclusions; restoring the page's scoping status prevented an unjustified inference that this was deployed infrastructure.

## Fixed-depth baseline and targeted reads

Actual project reads:

| Scope | CLI stdout bytes | Compact evidence bytes, same record format | Observed wall time |
| --- | ---: | ---: | ---: |
| Root depth 0 | 498 | 97 | 5.67 s |
| Root depth 1 | 27,994 | 13,266 | 1.32 s |
| Root depth 2 | 241,267 | 148,746 | 3.39 s |
| Entire root recursively | 1,379,546 | 1,107,812 | 3.49 s |
| Entire linked Trace project recursively | 41,986 | 35,170 | recorded in raw metrics |

The depth-0 outlier demonstrates why these single calls cannot establish a speed curve. Root recursion also does **not** follow links to separate notes: depth selection and graph navigation are different actions.

For the video question, the delivered router variant fetched only the hub and Map Features, receiving 33,048 bytes from Craft. It returned a 2,644-byte compact packet containing 1,246 bytes of source records. Total observed time was 4.57 s, with four Jev calls and 53,488 reported input tokens. The earlier variant returned 2,140 bytes with less surrounding context in 5.09 s; do not interpret that timing difference as a demonstrated optimization.

A competent main agent could also select Map Features after one shallow read and fetch the same 33 KB in two calls. Jev's potential advantage is doing that navigation internally and returning a compact packet in **one outer tool invocation**. It does not eliminate the Craft reads and was not faster than a single broad API read in this observation. Whether avoiding a main-agent continuation and excess context pays off requires an actual agent A/B.

## Cost and command advice

[TypeSafe's published model price](https://docs.typesafe.ai/models) is $0.042 per million input tokens with output free. The following estimates multiply observed API usage by that price; they are not reconciled invoice amounts and exclude Craft costs and the main agent.

| Trial | Craft commands | Jev calls | Total seconds | Packet bytes | Estimated Jev USD |
| --- | ---: | ---: | ---: | ---: | ---: |
| Broad capabilities | 2 | 4 | 5.22 | 4,317 | 0.002296 |
| Video routing, initial | 2 | 4 | 5.09 | 2,140 | 0.002260 |
| Video routing, context-preserving variant | 2 | 4 | 4.57 | 2,644 | 0.002246 |
| Linked caching, corrected candidate frontier | 3 | 4 | 10.56 | 1,517 | 0.003424 |
| Updated nested architecture | 2 | 4 | 3.49 | 2,189 | 0.001533 |
| Answer already shallow | 1 | 3 | 2.61 | 1,555 | 0.001394 |
| Missing-agreement control | 1 | 3 | 3.64 | 1,414 | 0.001392 |

The link-search command returned 741 KB before local filtering; model calls accounted for about 1.88 seconds of the corrected 10.56-second run. Cheap classification does not repair an expensive discovery API. Caching reusable graph metadata or a correctly maintained local link index may matter more there, but neither was built in this experiment.

The standalone advisor used one 0.517-second call / 16,541 input tokens, approximately $0.000695. For the video question it ranked:

1. Read Map Features at depth 1: preferred targeted command.
2. Full-project recursion: likely excessive, though it may contain the answer.
3. Existing shallow context: incomplete for that question.
4. Root depth 2: expands unrelated branches.
5. Root depth 0: unlikely to help.

The scoring formula was `answer_likelihood - 0.35 * overkill_likelihood`, chosen for this prototype, not calibrated. Individual model scores were not logically monotonic: a full recursive read scored lower for answer likelihood than a branch it contains. These are advisory rankings, not reliable probability certificates. Expose plain-language categories to the main agent, along with actual command scope and source evidence, rather than presenting scores as established accuracy rates.

## Failures and fixes retained in the record

- **Candidate frontier bug:** the first implementation kept only the first 40 candidates. Newly discovered children could fall behind old backlinks and become invisible. The delivered version permits 120 candidates and reports omission counts. A regression test covers new children appearing after 50 older backlink candidates. The first linked trial (22.02 s / $0.002621) is retained but not used as the corrected result.
- **Dropped qualification:** relevance-only excerpt selection removed the infrastructure note's scoping status. Deterministic retention now adds the page title, first two non-heading text blocks, and nearest section headings for selected evidence. This restores native context; it does not prove all possible qualifications are preserved.
- **Over-conservative completion:** initial sufficiency was 0.85 for the literal linked-project answer, below the arbitrary 0.90 gate. Even the final video evidence, containing the relevant facts, scored only 0.56 on the broad all-facts question. No run should be sold as validated autonomous completion based on that gate.
- **Atomic checks differ:** an evidence-only diagnostic scored the video's three explicit requirements 0.97, 0.96 and 0.96, while broad sufficiency remained lower. Architecture coverage remained mixed even after context repair (0.77 / 0.98 / 0.63). Use explicit missing-fact signals and conservative handoff; do not tune one threshold on these examples and claim reliability.
- **Empty search versus link discovery:** a plain regex search for Sumr returned zero in this session, while include-mode search used by backlinks returned matches. The experiment uses the demonstrated include path and exact-link filtering. No search-completeness claim follows.

Six offline regression tests pass: frontier visibility, cycle avoidance, relation deduplication, context preservation, verbatim source retention, and command-identifier rejection. The final router was smoke-tested against the live video question. The standalone advisor and coverage checker were also exercised live. No automatic hook, model-generated shell execution, native formatting change, or note mutation was installed.

## Proposed next interface and evaluation

Two modes are worth carrying forward:

- **Advise:** after a shallow read, return a few valid next commands labeled likely useful, probably unnecessary, or too broad, with the specific missing evidence they target. Jev can choose among predefined reason codes; generated prose is unnecessary.
- **Retrieve:** accept `{question, rootId, intent, evidenceRequirements, maxReads, maxBytes, timeBudget}`. Run bounded branch reads internally, then return exact evidence, source IDs, achieved/missing requirements, unvisited branches and optional next commands. Do not expose the model's hidden reasoning; a short explicit retrieval objective is sufficient.

Prefer per-branch expansion to incrementing depth for an entire page. Fetch shallow previews once, reuse acquired evidence, deduplicate backlinks, detect cycles and preserve page/heading/toggle context. A collapsed toggle is not a reason to omit its content. Estimate each action's expected new evidence and volume separately from current evidence sufficiency. On exhaustion or uncertainty, return partial evidence to the main agent rather than looping indefinitely or claiming absence.

A valid savings test must compare complete main-agent tasks: ordinary Craft tools, the advisor, and the bounded retriever, on held-out user questions. Measure answer correctness with required facts/citations, main-agent turns and input/output tokens, Jev usage, Craft requests/bytes, and wall time. Use the same question set and predefined criteria; include literal lookups, old-versus-new plans, multi-branch answers, renamed links, misleading titles, unanswerable requests and native-context qualifications. Net savings = avoided main-model work minus Jev and added retrieval costs. This turn establishes feasibility and concrete failure modes, not that net savings number.
